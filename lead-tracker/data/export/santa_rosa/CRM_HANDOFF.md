# Santa Rosa Lead Batch — CRM Handoff

Enriched, scored lead data ready for CRM ingest. Hand this whole file to the CRM
builder along with the two CSVs below.

## Files

| File | Rows | What it is |
|------|------|------------|
| `santa_rosa_ENRICHED_crm.csv` | 2,008 | **Full dataset** — every lead, original schema + scoring columns. Ingest this. |
| `santa_rosa_FOCUS.csv` | 242 | **Grade-A shortlist** — the leads to work first this batch. Derived view (a subset of the above), outreach-shaped columns. Optional; you can recreate it from the full file by filtering `lead_grade == "A"`. |

Both are UTF-8, comma-delimited, with a header row. Generated by
`scripts/enrich_for_crm.py` over the deep-enriched source.

## TL;DR for the CRM

- Ingest `santa_rosa_ENRICHED_crm.csv`.
- **Dedup key = `fingerprint`** (stable 12-char hash of name+site+phone+city; safe across re-runs).
- **Default sort = `lead_score` desc.** **Default filter = `lead_grade in (A, B)`.**
- The "work now" queue = `lead_grade == "A"` (242 leads) — all premium/solid category, all reachable on email+phone, all with a dead/weak/no website.
- Surface `recommended_action` verbatim in the lead card; it's a plain-English next step.

## The scoring model (so you can build filters/sorts that mean something)

`lead_score` is 0–100, the sum of three axes plus small bonuses:

| Axis | Max | Meaning |
|------|-----|---------|
| **need** | 40 | How badly they need our product. `NO website` 40 · `site dead` 39 · `thin/placeholder` 34 · `weak/DIY` 30 · `modern site` 10. Field: `need_signal`. |
| **value** | 30 | Revenue tier of the business type. `premium` 30 · `solid` 23 · `modest` 15 · `low` 7. Fields: `category_value`, `category_tier` (1–4). |
| **reachability** | 22 | Best channel. `email+phone` highest, then email, then phone-only, then none. Field: `reach_channel`. Valid (MX-checked) email scores above unverified. |
| bonuses | +8 | owner email known (+5), owner name known (+2), active social (+3). |

`lead_grade` is the score bucketed, **calibrated to this batch's distribution**:
`A >= 85` (242) · `B 70–84` (866) · `C 55–69` (814) · `D < 55` (86).

> A grade-A lead means: high-need (no/dead/weak site) **and** (premium category
> **or** email-reachable). Those are the businesses most worth a web-design pitch
> that we can actually contact.

## Suggested CRM lead mapping

```
name            <- Business
category        <- Category
email           <- Email            (status: email_status)
phone           <- phone_e164       (valid: phone_valid)
website         <- Website
address         <- Address
city            <- City
score           <- lead_score
grade           <- lead_grade
priority_reason <- recommended_action
dedup_id        <- fingerprint
tags            <- [category_value, reach_channel, site_quality, need_signal]
raw             <- (keep the whole row for audit)
```

## Ingest notes / gotchas

- **Dedup on `fingerprint`**, not name — names collide and re-runs would double-insert.
- `email_status == invalid` mostly means *no email present*, not a bad address — don't drop those leads; 879 of them are still phone-reachable (`reach_channel == phone`).
- Don't treat `free`/`role` email flags as disqualifiers — for a web-design pitch a contractor on a gmail address is a *stronger* lead.
- If the CRM repo normalizes line endings to LF, run the CSV through that normalization before commit.
- This batch is **Santa Rosa only**. The deep source also covers Sonoma + 5 bordering counties; the same `enrich_for_crm.py` regenerates an equivalent file per region.
